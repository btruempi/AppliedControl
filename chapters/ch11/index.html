    Chapter 11: Emerson DeltaV DCS & Safety Systems

    Learning Objectives

    • Remember: Identify the three tiers of the DeltaV system architecture and state the function of each
    • Understand: Explain how DeltaV CHARMs differ from traditional I/O cards and why this reduces installed cost
    • Apply: Describe the engineering workflow for adding a new PID control loop in DeltaV, from I/O assignment through parameter configuration to commissioning
    • Analyze: Distinguish between a DeltaV DCS loop and a DeltaV SIS logic solver, and explain why the same I/O cannot be shared between safety and basic process control
    • Evaluate: Build the business case for migrating a legacy Honeywell TDC-3000 system to DeltaV, addressing migration risk, system architecture, and lifecycle cost

    11.1 DeltaV System Architecture Overview

    Emerson DeltaV is a modern distributed control system (DCS) built on an Ethernet-based architecture with three primary tiers:

    Tier 1: Field I/O Layer

    Physical connection between field devices (transmitters, control valves, on/off valves, motors) and the DeltaV controllers. I/O can be:

    • Traditional I/O cards: Wired to terminal blocks in marshalling cabinets; each card handles 8–16 channels of a specific signal type (AI, AO, DI, DO)
    • CHARM I/O (Electronic Marshalling): Each field wire terminates on a CHARM (Characterization Module) — a per-channel intelligent I/O module that can be any signal type (AI 4–20mA HART, AO, DI, DO) configured in software. No marshalling cabinet; no rewiring to change signal type.

    Tier 2: Controller Layer

    DeltaV Controllers (MD, MD Plus, MX, and S-series) execute the process control strategy:

    • Deterministic scan rate (typically 100–500 ms for process control)
    • Built-in redundancy (primary + secondary controller pairs with bumpless switchover)
    • Direct HART integration — reads secondary variables from HART devices without additional hardware
    • FOUNDATION Fieldbus interface — runs FF segments directly from the controller
    • OPC connectivity to plant historian, MES, and ERP systems

    DeltaV Controller sizing:

    Controller model I/O capacity Control loops Applications
    MD 750 I/O ~200 loops Small units, remote skids
    MD Plus 1200 I/O ~400 loops Medium process units
    MX 2500 I/O ~800 loops Large process units
    S-series Scalable 1000+ loops Large integrated systems

    Tier 3: Workstation / Network Layer

    • DeltaV Operate (HMI): Operator interface — process graphics, alarms, trends
    • DeltaV Operate for Batch: Recipe execution, batch reporting
    • DeltaV Insight: Continuous historian; feeds Emerson Asset Management Suite
    • DeltaV Live: Modern HTML5 operator interface replacing legacy DeltaV Operate
    • Engineering workstation: DeltaV Explorer for configuration, DeltaV Diagnostics

    11.2 CHARMs Electronic Marshalling — The Game Changer

    Traditional DCS I/O requires: 1. Field wire → marshalling cabinet terminal block 2. Jumper wire → specific-type I/O card (AI, AO, DI, DO) 3. I/O card → controller

    If a signal type changes (e.g., a 4–20 mA transmitter becomes a HART transmitter, or a digital output needs to change rack location), hardware rewiring is required.

    DeltaV CHARMs eliminate marshalling: - Each field wire connects directly to a CHARM I/O module - CHARM type is configured in software — one module handles AI, AO, DI, or DO - CHARMs slide into CIOC (CHARM I/O Card) carriers; carriers connect to controllers via Ethernet - No marshalling cabinet required → significant cost reduction in new construction

    CHARM economic impact on a 1,000-point system:

    Item Traditional I/O CHARM
    Marshalling cabinet 4 cabinets × $15,000 Eliminated
    Rewiring cost (engineering changes) $500/point × 50 changes $0 (software)
    Installation labor Higher (terminal block jumpers) Lower (one termination)
    Engineering time Higher (I/O assignment fixed early) Lower (late binding)

    Late binding is the key concept: with CHARMs, the I/O type can be determined after field installation, allowing the DCS configuration to proceed in parallel with construction.

    11.3 DeltaV Control Strategy

    Function Blocks

    DeltaV uses IEC 61499-inspired function blocks for control strategy configuration:

    Block Function Common use
    AI (Analog Input) Reads a process measurement from a field device Any transmitter
    AO (Analog Output) Writes a control signal to a final element Control valves, VFDs
    DI / DO Digital input / output Pumps, motors, solenoids
    PID PID control algorithm All feedback loops
    Ratio Calculates a ratio between two measured variables Flow ratio control
    Lead/Lag Dynamic compensation Feedforward, cascade
    SPLITTER Splits one output to two AO blocks Split-range control
    Sequence Sequential logic for step-by-step operations Startup/shutdown, batch

    Building a PID Loop in DeltaV

    1. Create module: In DeltaV Explorer, create a Control Module assigned to the appropriate controller
    2. Add I/O: Assign the AI block to the CHARM channel connected to the transmitter; assign the AO block to the CHARM channel connected to the DVC6200
    3. Add PID block: Wire AI → PID → AO
    4. Configure PID: Set Kp, Ti, Td; configure engineering units, scale limits, alarm limits
    5. Configure AO: Set action (direct/reverse), ranging, output limits
    6. Download: Transfer module to controller; controller begins execution
    7. Commission: Place in Auto mode; observe process response; tune PID gains
    8. HART reads: Enable HART secondary variable reads on the AO block to capture DVC6200 diagnostic data into the historian

    11.4 DeltaV Advanced Control

    Cascade Control

    DeltaV cascade loops connect two PID blocks: the primary (outer) controller sets the setpoint of the secondary (inner) controller. The secondary loop must be at least 5× faster than the primary.

    Example: Reactor temperature cascade - Primary: Temperature controller → sets cooling water flow setpoint - Secondary: Flow controller → positions the cooling water control valve

    Configuration: Set primary PID output to target the secondary PID's Remote Setpoint parameter.

    Model Predictive Control (DeltaV PredictPro)

    For multi-variable processes with interactions between loops, DeltaV PredictPro implements a model predictive controller (MPC) as a DeltaV module. MPC: - Simultaneously controls multiple outputs (MVs — manipulated variables) - Handles constraints (max/min limits) explicitly - Predicts process response using a dynamic model - Particularly valuable in distillation, reaction, and heat integration systems

    Applied Control has DeltaV PredictPro commissioning capability — a significant differentiator in the DCS market.

    Batch Control (DeltaV Batch)

    DeltaV Batch implements the ISA-88 batch control standard: - Recipe management: Master, control, and batch recipes - Procedure execution: Procedural elements (procedures, unit procedures, operations, phases) - Equipment arbitration: Allocates shared equipment between concurrent batches - Electronic batch records: Automatic documentation of every parameter and event

    11.5 DeltaV Safety Instrumented System (SIS)

    DeltaV SIS is Emerson's integrated safety system, built on the same platform as DeltaV DCS but architecturally separated to meet IEC 61511 requirements.

    Safety vs. Basic Process Control

    IEC 61511 requires independence between the Safety Instrumented System and the Basic Process Control System:

    Requirement DeltaV DCS DeltaV SIS
    Physical I/O separation Shared (CHARM) Dedicated SIS I/O
    Controller separation Shared controller Dedicated SIS logic solver
    Failure independence Not required Required — common cause failure analysis
    SIL certification Not certified TÜV certified SIL 2/3 capable
    Proof test requirements None Per IEC 61511

    DeltaV SIS Logic Solvers are TÜV-certified, redundant (1oo1D, 1oo2, 2oo3 voting architectures) dedicated controllers for SIS applications.

    Safety Instrumented Functions (SIFs)

    A Safety Instrumented Function (SIF) is a combination of sensor(s), logic solver, and final element(s) designed to achieve a required Safety Integrity Level (SIL):

    SIL Probability of Failure on Demand (PFD) Risk reduction factor
    SIL 1 0.1 – 0.01 10 – 100
    SIL 2 0.01 – 0.001 100 – 1,000
    SIL 3 0.001 – 0.0001 1,000 – 10,000

    Partial Stroke Testing in DeltaV SIS

    For SIS final elements (shutdown valves), Partial Stroke Testing (PST) is required by IEC 61511 to maintain SIL certification between major proof tests. DeltaV SIS integrates with the Fisher DVC6200 to:

    1. Command the SIS valve to stroke 10–15% from its normal open position
    2. Verify the valve moves (position feedback confirms mechanical integrity)
    3. Return to open position
    4. Log the test result with timestamp for PSM documentation

    PST can be performed from the DeltaV SIS engineer workstation without taking the SIS offline — satisfying the proof test coverage requirement with minimal process disruption.

    11.6 DeltaV Migration — The Legacy DCS Opportunity

    A massive installed base of legacy DCS systems — Honeywell TDC-3000, Honeywell PHD, Foxboro I/A, ABB Advant, Siemens APACS, Bailey Net90 — is approaching end-of-life. Emerson positions DeltaV as the migration platform.

    Migration Value Proposition

    Legacy pain point DeltaV migration solution
    Spare parts unavailable New hardware on modern components
    No vendor support 10+ year Emerson support commitment
    No HART integration Full HART multi-variable reads standard
    No advanced diagnostics AMS Device Manager, DeltaV Insight historian
    Inflexible I/O CHARM electronic marshalling
    Dated operator interface DeltaV Live HTML5 graphics

    Smart Commissioning — Migration Without Shutdown

    Emerson's Smart Commissioning methodology allows DeltaV to be installed and configured while the plant is still running on the legacy system. Field devices are re-terminated to DeltaV CHARM I/O one system at a time (unit by unit), cutting over during maintenance windows — minimizing the risk of a full plant shutdown.

    Applied Control has executed DeltaV migrations from multiple legacy platforms. The migration project typically involves:

    1. Assessment phase: Document existing control strategy, I/O list, loop performance history
    2. DeltaV system design: Controller sizing, I/O architecture, CHARMs layout, network design
    3. Configuration: Import/convert control strategy; configure all loops, graphics, historians
    4. Factory Acceptance Test (FAT): Simulate all I/O; validate control strategy in the Applied Control shop
    5. Site installation: Rack installation, CHARM wiring, network commissioning
    6. Cutover: Unit-by-unit migration with legacy and DeltaV running simultaneously until complete
    7. Training: Operator and maintenance training; Applied Control on-site during first month

    Chapter Summary

    DeltaV's three-tier architecture (field I/O, controllers, workstations) provides a complete DCS platform from sensor to historian. CHARMs Electronic Marshalling eliminates traditional marshalling cabinets, enables late binding of I/O types, and significantly reduces installation cost and engineering change management burden. DeltaV SIS provides TÜV-certified SIL 2/3 logic solver capability on the same platform as the BPCS, with integrated PST capability through the DVC6200. The massive installed base of legacy DCS systems approaching end-of-life represents a multi-year migration opportunity that Applied Control is positioned to capture with DeltaV system expertise, field service capability, and Fisher/Rosemount instrumentation to populate the new system.
